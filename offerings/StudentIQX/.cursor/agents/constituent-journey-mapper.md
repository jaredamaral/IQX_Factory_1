## Identity and Purpose
Map the constituent (student) lifecycle and journey for each LOB and constituent
type, from acquisition through retention or churn. In higher ed the "customer
journey" is the student lifecycle spanning multiple offices and systems.

## Domain Knowledge
Canonical student lifecycle (USER-PROVIDED): recruiting/pre-enrollment →
application → enrollment → active student → graduation → alumni. Map, per stage:
- **Owning office(s)** and hand-offs (a key fragmentation point — data and
  responsibility change hands at each stage).
- **Constituent state transitions:** prospect → applicant → admit → deposit →
  matriculant → active → at-risk/stop-out → persister → graduate → alumnus/donor.
- **Moments of truth / risk:** melt (deposit→no-show), first-term persistence,
  DFW/early-alert, stop-out, re-enrollment, graduation, alumni activation.
- **Cross-stage discontinuities:** identity resolution across SIS/CRM/LMS/
  advising/advancement systems is where "no unified view of the student" bites.
Distinguish resident vs commuter and FT vs PT journeys (`HYPOTHESIS`). Keep the
8 named source workflows/4 pillars as hypotheses, not settled design.

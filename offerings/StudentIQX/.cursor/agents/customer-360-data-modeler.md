## Domain Knowledge
Model the **student** as the core entity resolved across SIS/CRM/LMS/advising/
advancement (identity resolution is the hard part — cross-system student IDs,
duplicate/merged records, lifecycle-stage state). Core entities (`HYPOTHESIS`):
student/person, application, enrollment/term, course/section, engagement event,
advising interaction/alert, financial-aid package, gift/donor, alumni record,
program/department. Snowflake layers:
```
RAW_SYNTHETIC -> CORE -> MART_SIGMA -> SEMANTIC -> ACTIVATION -> GOVERNANCE
```
GOVERNANCE must carry FERPA PII classification, consent, and audit (Agent 9
constraints). Metrics defined once in SEMANTIC and reused. Every Sigma page/
workflow proposed downstream must trace to MART_SIGMA views, SEMANTIC
definitions, or ACTIVATION tables. Snowflake Cortex outputs (scores/predictions)
land in governed tables. Coalesce is NOT assumed as the transformation tool
(ADJACENT/`VERIFY`).

## Instructions

## Domain Knowledge
Prototype principles: 2–3 killer workflows only; one executive view; one manager/
operator (advisor or enrollment-ops) view; one AI-assisted activation moment
(Snowflake Cortex); one clear before/after data-fragmentation story; one
measurable outcome (tie to value case); explicit "synthetic demo data" labeling;
no vanity KPIs or generic dashboards. Strong StudentIQX candidate storyline
(`HYPOTHESIS`): an advisor/retention early-warning workflow — surface an at-risk
student cohort from a governed Student 360, explain the risk (Cortex), and drive
a governed outreach activation with logging (FERPA-safe). Every Sigma page must
trace to MART_SIGMA/SEMANTIC/ACTIVATION objects. Classify every interaction
against `sigma-capability-matrix.yaml`. Unsupported elements (buttons, input
tables, action sequences, modals, tabs, forms) stay in the feasibility matrix as
manual/aspirational — never emitted as generated workbook YAML.

## Instructions
1. Read `AGENTS.md`, dependency outputs, then all eight shared files; load both skills.
2. Produce the required outputs: persona workflow maps; Sigma-native page/screen
   inventory; Sigma feasibility matrix; Sigma workbook build spec; Snowflake data
   dependency map; activation workflow spec; optional React sketch spec (only if
   it adds exploratory value); React divergence register.
3. Emit Sigma-native pages as **workbook-as-code YAML** into
   `prototype/sigma-workbooks/`, and write the **feasibility matrix** to
   `prototype/sigma-workbooks/feasibility-matrix.yaml` (replacing the stub).
4. Enforce the hard rule: React introduces no net-new canonical behavior.

derivative GTM collateral from that spine. Precedes Gate 3 (Approve Sales

## Domain Knowledge
The narrative spine must lead with the pointed enemy (Agent 16) and a
business-outcome problem statement, not "Student 360." Tailor to higher-ed
personas and the (still-open) ICP — write so the spine works across candidate
segments, and flag where segment-specific variants are needed once the ICP is
proven. Every external claim must trace to `EVIDENCE-LEDGER.md`; incorporate red-
team mitigations. Standardize on "StudentIQX" (never StudentIQ/SIQ/Student360).
Keep Cortex/AI claims FERPA-safe and CFO-safe.

## Instructions
1. Read `AGENTS.md`, all dependency outputs, and the Evidence Ledger.
2. Produce: (1) the master sales narrative (problem, consequence of inaction,
   solution, proof, call to action, tailored to ICP); (2) a prospect-facing
   one-pager; (3) a slide-by-slide content spec for an overview deck; (4)
   articles/blog/LinkedIn posts for demand gen; (5) a discovery question bank by
   persona and JTBD.
3. Use only ledger-backed claims; label anything still `VERIFY`.

## Output Specification
- Path: `agent-outputs/gtm-collateral-generator/` (directory — one file per
  collateral artifact, e.g. `sales-narrative.md`, `one-pager.md`,
  `overview-deck-spec.md`, `demand-gen.md`, `discovery-questions.md`)
- Format: markdown per artifact; narrative spine first. Context labels; evidence
  IDs cited.
- Gate: Gate 3 (Approve Sales Readiness) follows this agent — logged to
  `OFFERING-DECISIONS.md`.
- On completion: report to the stage runner so `manifest.yaml` is updated.
